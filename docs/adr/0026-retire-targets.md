# 0026: target を退役させる

- ステータス: 採択
- 日付: 2026-09-29

## 背景

[ADR 0008](0008-no-purge-in-mvp.md) は MVP から purge（`Target`，`Run`，
`AuditEvent` の削除）を外し，target を止める手段を無効化（`enabled = false`）
だけにした．この判断は今も正しい．ただし運用が始まると，無効化だけでは
片付かないものが出てきた．

- **テスト用の target が残り続ける．** 動作確認で作った target は，使い終わった
  後も一覧に並び続ける．無効にしても行は消えず，一覧は日ごとに読みにくくなる．
- **名前が永久に塞がる．** 1 つの名前（`fqdn` と各 `additionalNames`）は 1 つの
  target にしか属せない．無効にした target も名前を持ったままなので，その名前を
  新しい target に使えない．`fqdn` は作成後に変えられず，`fqdn` の列は一意制約を
  持つので，「間違えて作ったので同じ名前で作り直す」，「CN を変えて旧 target を
  片付ける」（[`docs/account-scoped-ca.md`](../account-scoped-ca.md)）といった
  ごく普通の操作もできない．

必要なのは，履歴を一切失わずに，その target を恒久的に運用から外して名前を
解放する操作である．ADR 0008 は将来の purge が満たすべき条件として，無効化とは
別の明示的な操作であること，監査されること，対象範囲が定められていることを
挙げた．ここで求めているものは purge よりずっと小さいが，同じ条件は満たすべき
である．

## 決定

target の **退役（retire）** を加える．purge は引き続き実装しない．

- `POST /api/v1alpha1/targets/{id}/retire`（admin のみ）．無効化とは別の，明示的な
  操作であり，無効化の副作用や自動的な帰結ではない．
- **前提**: target が無効であること，実行中（queued/starting/running）の run が
  ないこと，まだ退役していないこと．満たさなければ `409`
  （`target_enabled`，`run_active`，`target_retired`）．
- **効果**（1 つのトランザクション）: `retired_at` と `retired_by` を記録し，
  target の名前をすべて解放し，その target の target ごとの ACME アカウントに
  保留中の EAB 投入要求があれば `cancelled` にし（封入済みペイロードは消す），
  監査イベント `target.retired` を書く．**何も削除しない**: `Target`，`Run`，
  `AuditEvent`，ACME アカウントの行はすべて残る．
- **退役済みの target**: `GET /targets/{id}` は読める．一覧は既定で除き，
  `?retired=include` で含める．変更（`PUT`，`enable`，`disable`，run の要求，
  EAB の投入）はすべて `409` `target_retired`．スケジューラは計画しない．
  スキーマのトリガも退役済みの行の更新を拒む．**元に戻す操作はない．**
  同じ名前を再び管理したければ，新しい target を作る．
- **範囲**: 退役が変えるのは Conductor のレジストリだけである．Certificate Store
  の証明書，Runner のアカウント状態，CA のアカウントには触れない
  （Conductor にはそのための権限がない．[ADR 0005](0005-conductor-never-touches-secrets.md)）．
  保存済みの証明書は更新されなくなり，期限で切れる．Store のオブジェクト名は
  FQDN から決まるので，退役した target と同じ名前の新しい target は，同じ
  Key Vault 証明書の新しいバージョンを書く．これは許容する．
- **ポリシー**: ポリシーの target 数と，ポリシー更新時の「既存の target をなお
  満たすか」の検査は，退役済みの target を数えない．退役済みの target は二度と
  run を持たず，証明書を発行しないので，ポリシーを厳しくしても害がない．
  ポリシーの削除はそもそもできず（トリガと API の不在），退役済みの target は
  `policy_id` の外部キーを持ち続ける．
- **スキーマ**（バージョン 6）: `targets.fqdn` の一意制約を，退役していない
  target の間だけの部分ユニークインデックスに置き換える．インライン `UNIQUE` は
  外せないので `targets` を作り直す．`runs` と `target_names` が `targets` を
  参照するため，この移行 1 つだけは外部キー検査を切って実行し（トランザクションの
  中では `PRAGMA foreign_keys` が効かないので，接続に対してトランザクションの前に
  切る），コミット前に `PRAGMA foreign_key_check` を通し，終わったら検査を戻す．
  `target_names` は退役していない target の名前だけを持つ（退役で行を消す）．

これは ADR 0008 が purge に課した条件を，purge でない操作として満たす．無効化と
は別の明示的な操作で，監査され，範囲は上に列挙したとおり定められており，
何も削除しない．ADR 0008 のステータスと決定は変えない．

## 結果

- 操作者はテスト用の target を一覧から外し，名前を再利用できる．履歴
  （実行履歴，操作記録）はいつまでも読める．「削除」ではないので，
  T11（無効化と purge の混同）の脅威は退役についても変わらない: 退役は
  Certificate Store の証明書を消さず，失効もさせない．GUI は確認に FQDN の
  入力を求め，証明書が残ることを明記する．
- 退役は不可逆である．誤って退役させた場合は，同じ名前で新しい target を作り，
  新しい run で発行し直す（EAB が必要な CA では新しい EAB も要る）．
- 名前の解放により，1 つの FQDN に複数の退役済み target の行と最大 1 つの
  現役の target が並びうる．FQDN で履歴を追うときは target の id を使う．
- Store の同名の証明書には，退役前の target が書いたバージョンと，新しい target が
  書いたバージョンが並ぶ．Key Vault の場合は，バージョンごとの履歴として
  そのまま残る．
- スキーマの移行が `targets` を作り直す．この移行は外部キー検査を切る唯一の
  ものなので，検査を通らなければ全体をロールバックし，移行テストで
  （前バージョンのデータベースに対して）行と参照が残ることを確かめている．
- 退役済みの target の増加は一覧の既定表示には影響しないが，データベースには
  残り続ける．purge が要るほどの量になったときは，ADR 0008 のとおり別の ADR で
  設計する．
